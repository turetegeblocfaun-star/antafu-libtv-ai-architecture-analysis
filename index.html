15. 建议架构 To-Be

蚂蚁阿福：Supervisor + Specialist + Reviewer

【建议设计】

  • 健康主控负责上下文、沟通与任务路由。
  • 检索、报告解析、药盒视觉为按需 Specialist Worker。
  • 独立 Medical Safety Reviewer 校验高风险表述、来源一致和旧建议失效。
  • Reviewer 只返回审校结果，由主控统一回答，避免多口径。

LibTV：Supervisor + DAG Workers + Validator

【建议设计】

  • 创作主控管理目标、确认、预算、任务与交接。
  • 剧本/角色/分镜/媒体 Worker 按 Skill DAG 和依赖启动。
  • Asset Validator 独立验证文件、引用、时长、风格和页面状态。
  • 所有任务使用 request_id、幂等键、版本 DAG 和计费事件。

16. 关键风险

P0

医疗错误与旧建议残留

阿福曾出现确定性过强和旧建议未失效。需版本化、证据映射和独立安全审校。

P0

任务/页面状态冲突

阿福“已停止/正在调用工具”和 LibTV“无回执/已有项目”都是完成与执行分离问题。

P0

重复调用与扣费

LibTV 无回执易诱发重复发送；项目已出现但来源不明。需 request_id、幂等和账本。

P1

来源一致性

阿福“引用2篇”与来源表1行不一致，削弱循证可信度。

P1

模态能力不一致

阿福 PDF 不能附加要求但图片可以；用户难以控制同一报告的解释边界。

P2

模型与 Skill 治理

LibTV 模型/Skill 数量多，需要版本、成本、能力漂移、版权和安全审计。
